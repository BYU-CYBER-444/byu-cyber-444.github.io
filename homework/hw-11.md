# HW 11 - Ansible Hardening Change Review
{: .no_toc }

## Purpose

Review a proposed Ansible change before it is applied to Linux systems. You will practice checking whether automation matches its security intent and reports failures honestly.


## Scenario

A team is preparing an Ansible update for its Rocky Linux servers. The approved baseline requires:

- SSH root login is disabled (`PermitRootLogin no`).
- IPv4 forwarding is disabled now and remains disabled after reboot.
- The `telnet` package is absent.
- `auditd` is enabled and running; a failure to enforce this must stop the rollout.

Review this excerpt from the proposed playbook. The line numbers are for reference only and are not part of the YAML.

```text
01  - name: Apply Linux baseline
02    hosts: linux
03    become: true
04    tasks:
05      - name: Set SSH root login policy
06        ansible.builtin.lineinfile:
07          path: /etc/ssh/sshd_config
08          regexp: '^PermitRootLogin'
09          line: 'PermitRootLogin yes'
10        notify: Restart sshd
11      - name: Disable IPv4 forwarding
12        ansible.builtin.command: sysctl -w net.ipv4.ip_forward=0
13      - name: Ensure telnet is absent
14        ansible.builtin.dnf:
15          name: telnet
16          state: absent
17        changed_when: false
18      - name: Keep auditd enabled and running
19        ansible.builtin.service:
20          name: auditd
21          enabled: true
22          state: started
23        ignore_errors: true
24    handlers:
25      - name: Restart sshd
26        ansible.builtin.service:
27          name: sshd
28          state: restarted
```
