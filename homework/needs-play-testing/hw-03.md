## Description

Production Active Directory environments accumulate stale accounts that become security liabilities - every dormant account is a credential an attacker can leverage without triggering recent-login monitoring. In this assignment you are the analyst handed a discovery report, not the one building the tooling from scratch: you'll run a provided audit script against a real AD environment, interpret its findings, and manually remediate what it flags.

You will be given access to a dedicated AD server for this assignment, seeded with a mix of stale-login accounts, expired-password accounts, accounts matching both conditions, an excluded service account, and a clean control account. You do not need to build or provision your own lab domain - work directly against the provided server.

### Part 1 - Run the Audit Script & Interpret Results (25 pts)

Download [hw-03-audit.ps1]({{ site.baseurl }}/homework/assets/hw-03-audit.ps1) - this is provided to you, you do not need to write it. It is a **read-only** discovery tool: it queries AD for enabled accounts that are stale and/or have expired passwords, excludes service accounts, and writes a CSV report. It makes no changes to Active Directory.

```powershell
param(
    [Parameter(Mandatory = $true)]
    [string]$Domain,

    [string]$SearchBaseDN,

    [string[]]$ExcludeList = @('svc-backup', 'svc-sql'),
    [int]$StaleDays = 90,
    [int]$PasswordDays = 180,
    [string]$OutputPath = "."
)
```

1. Run the script against the AD server you were given, passing `-Domain` for the DNS domain name of the environment you were assigned (e.g. `-Domain lab.local`) - the script derives its LDAP search base from this. If you were handed a domain controller hostname instead of a DNS domain name, pass that as `-Domain` and set `-SearchBaseDN` explicitly (e.g. `-SearchBaseDN "DC=lab,DC=local"`). Run it from a machine with the `ActiveDirectory` module (RSAT) available and a session/credentials against that domain, e.g.:

   ```powershell
   .\hw-03-audit.ps1 -Domain lab.local -OutputPath .\reports
   ```

   Or, against a specific domain controller with a search base set explicitly and non-default thresholds:

   ```powershell
   .\hw-03-audit.ps1 -Domain dc01.lab.local -SearchBaseDN "DC=lab,DC=local" -StaleDays 60 -PasswordDays 120 -OutputPath .\reports
   ```
2. Open the resulting `stale-accounts-YYYY-MM-DD.csv` and confirm you understand every row: which threshold(s) each account tripped (`Reason`: `stale` / `expired-password` / `both`), and why the excluded/service accounts were correctly left out.

### Part 2 - Manual Remediation (35 pts)

For each account flagged in the CSV (excluding any the script already excluded), remediate it by hand against the provided AD server:

1. **Disable** the account.
2. **Set the `Description` attribute** to `[DISABLED] Manual review - stale >90d. Disabled by: <your name> on <today's date>` (use the actual `-StaleDays` value the script ran with, not the literal text `90`).
3. **Move the account** to an `OU=Disabled,OU=Users,<your domain's DN>` OU in the domain you were given (e.g. `OU=Disabled,OU=Users,DC=lab,DC=local` for a `lab.local` domain) - create the OU first if it doesn't already exist.
4. **Log every action you take** to `hw-03-remediation-log.txt` - one line per account with a timestamp, the `SamAccountName`, and the action taken. You may do this by hand, with a short PowerShell one-liner, or with ADUC plus a manually-maintained log file; there's no required script for this part, but the log must be real and match what you actually did.

If you hit an error remediating any account (permissions, an already-existing OU, a locked object, etc.), don't just skip it silently - note what happened and how you resolved it; this feeds directly into the Part 3 write-up.

### Part 3 - Write-Up (20 pts)

Add a `## Write-Up` section to your PR's copy of `homework/hw-03.md` (or a linked doc) and answer each question below under its own subheading. Each answer should be a short paragraph (3-6 sentences) grounded in what you actually observed running the script and remediating accounts against the provided AD server, not a generic textbook answer.

1. **Dormant account risk** - What is the security risk of dormant accounts beyond just "wasted licenses"? Cite one real-world breach where stale credentials were exploited (name the incident and link a source).
2. **Quarantine OU design** - You moved disabled accounts to a separate OU rather than deleting them immediately. What is the operational justification for this design? How long should accounts remain there before deletion, and who should approve the final deletion?
3. **Staleness signal limitations** - Identify one limitation of using `LastLogonDate` as the sole staleness indicator and propose a more reliable alternative or supplement.
4. **Remediation issues encountered** - Describe any error or unexpected behavior you hit while remediating accounts by hand, and how you resolved it. If nothing went wrong, describe what could go wrong at larger scale (hundreds of accounts) with a fully manual process like this one, and how you'd address it.

Grading looks for: correctness of the security reasoning, a real (not fabricated) breach citation, and answers specific enough that they couldn't have been written without actually running the script and doing the remediation.

### Part 4 - LDAP Filter Syntax (20 pts)

Stale-account remediation and directory queries in general both come down to writing correct LDAP filters. Given the abbreviated directory layout below (base DN `dc=corp,dc=lab`):

```
dc=corp,dc=lab
 ou=People
    uid=jsmith   (cn=Jane Smith, memberOf=cn=NetworkAdmins,ou=Groups,dc=corp,dc=lab, userAccountControl=512)
    uid=bvance   (cn=Bob Vance, memberOf=cn=HelpDesk,ou=Groups,dc=corp,dc=lab, userAccountControl=514)
    uid=tlowe    (cn=Tara Lowe, memberOf=cn=NetworkAdmins,ou=Groups,dc=corp,dc=lab, userAccountControl=66050)
 ou=Groups
    cn=NetworkAdmins
    cn=HelpDesk
```

(`userAccountControl` follows the AD convention: `512` = normal enabled account, `514` = disabled account, `66050` = disabled + password never expires.)

Write the exact LDAP search filter string for each of the following:

1. Every enabled account that is a member of `NetworkAdmins`.
2. Every account that is **either** disabled, **or** has password-never-expires set (you'll need the `userAccountControl` bitwise matching rule OID `1.2.840.113556.1.4.803`).
3. A filter that returns `uid=jsmith` **or** `uid=tlowe` by name, using the `|` OR operator explicitly.
